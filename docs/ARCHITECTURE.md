# Architecture

The repository contains two related research stacks sharing data, validation,
and execution utilities.

## System map

```text
Deribit/Binance data
        |
        +--> downloader --> TSRV --> vol_model --> vol_arb
        |                                      |
        |                                      +--> honest option marking
        |                                      +--> research dashboard
        |                                      +--> deribit_paper (replay/testnet)
        |
        +--> src/signal_engine --> src/live (directional demo/testnet)

Shared: src/afml, validation, configs, tests
```

### Volatility and options stack

1. `downloader/` acquires Deribit options/DVOL and Binance trade data.
2. `TSRV/` converts trade streams into causal realized-volatility features.
3. `vol_model/` builds forward labels and walk-forward forecasts.
4. `vol_arb/` aligns forecasts with option surfaces and evaluates executable
   structures, fees, fills, and PnL.
5. `deribit_paper/` preserves replay/testnet machinery. Its V2 preset is
   historical and is not a validated deployment target.

### Directional stack

`src/signal_engine/` contains the older/parallel multi-asset feature,
portfolio, close-model, slippage, and execution pipeline. `src/live/`
contains orchestration and exchange adapters, including legacy real connectors;
while no strategy is validated, only demo/testnet research is authorized. S5
research belongs to this stack even when its reports are generated by scripts
beside the options research.

## Module contracts

### Time and causality

- A decision stamped at time `t` may use only information observable by
  `t`.
- Resampled features use the last completed source bar, never a still-forming
  bar.
- Forward labels describe `(t, t + horizon]` and are joined separately from
  features.
- Fold preprocessing, clipping, normalization, and feature selection are fit
  on training data only.

### PnL and execution

- Forecast quality and trading PnL are different claims.
- Option PnL must be marked from executable option premiums or an independently
  justified market proxy. Per-bar calibration movement is not a fill.
- Signal, sizing, fees, slippage, hedge PnL, and option-mark PnL remain
  separately inspectable.
- A realism gate compares independent series. Comparing a result with itself
  is a structural assertion, not validation.

### Artifacts

Version control contains code, tests, configuration templates, and canonical
documentation. It does not contain raw market data, model weights, caches,
plots, or run output.

Existing local artifact locations such as `data/`, `experiments/cache/`,
`vol_model/output/`, and `vol_arb/output/` remain supported as local state
for this cleanup. New code should centralize path resolution so a later
mechanical migration to an external artifact root can be performed with
checksums rather than ad-hoc moves.

## Entry points

```text
python -m downloader
python -m TSRV.run_tsrv_series
python -m vol_model.run_walkforward_pruned_svi_har_pd
python -m vol_arb.run_pipeline
python -m vol_arb.run_backtest
python -m live
python -m deribit_paper
```

The editable package installs the top-level packages found under `src/`
(`afml`, `evaluation`, `live`, `signal_engine`, and `strategies`).
`TSRV`, `vol_model`, `vol_arb`, `deribit_paper`, and `downloader`
are repository workflows and currently run from a checkout.

`scripts/` contains orchestration and one-off research drivers, not reusable
library code. A script name or successful exit is not a promoted result; the
validation ledger remains authoritative.

## Known structural debt

- Importable code is split between `src/` and root workflow packages. Move it
  into one `src/ml_trading_system/` namespace only as a dedicated atomic
  refactor with updated entry points and tests.
- `vol_model` depends on `vol_arb.paths` while some `vol_arb` research
  imports `vol_model`. Path resolution belongs in a neutral module.
- `experiments/` is intentionally a flat provenance tree for now. Promote
  reusable implementations into canonical packages; do not add compatibility
  shims at the old path.
- The former add-only wrappers under `vol_arb/_patches/` were removed.
  Their suspected defects are tracked in `docs/KNOWN_ISSUES.md` until
  reproduced and fixed in the real callers.
- Data-dependent tests need an explicit integration marker, configurable
  artifact root, and a clear skip when local fixtures are absent.
